## 3. Kernel-level dependency graph (depgraph, depquery)

This is the analysis the paper relies on.

```bash
cd evidence/conescan && cargo build --release
mkdir graph && ./target/release/depgraph graph ../depgraph/watch_names.txt < /path/to/solution.ndjson
# one pass, about 8 minutes, peak memory about 17 GB
# writes graph/nodes.tsv, graph/edges.bin, graph/projs.tsv, graph/watch_hits.tsv, graph/depgraph_summary.txt
shasum -a 256 graph/edges.bin graph/nodes.tsv     # compare with ../depgraph/SHA256SUMS

# names of all constants of `import Mathlib` at the pinned version (run inside the project of section 5,
# which has the official Mathlib cache); or unpack ../depgraph/mathlib_names.txt.zst
lake env lean ../depgraph/DumpNames.lean          # writes mathlib_names.txt (771,129 names)

python3 -I ../depgraph/depquery.py graph mathlib_names.txt query
python3 -I ../../paper/make_tables.py query ../../paper   # regenerates every graph-derived number in the paper
```

`depgraph` stores the expression DAG of the export and, for every declaration record, walks the DAG of its type and
of its value, recording the declarations referred to (constants, and the structure named by a projection). Type
edges and value edges are kept apart. It also records every `proj S i e` node and every direct reference to a name
listed in the watch file (needed for recursors, which share a graph node with their inductive type).
`depquery.py` answers reachability questions: dependency cones, statement cones, dependents, and the split between
library declarations (names present in the Mathlib environment) and declarations of the release.
Our outputs are in `evidence/depgraph/` (`query/depquery_report.txt` is the human-readable summary).

It is a dependency analyser, **not** a type checker.

## 3b. The earlier single-pass analyser (conescan)

Used for the first version of the audit and kept for the record. **Known limitation:** taint is assigned when an
expression node is created, and the exporter emits the expressions of an inductive declaration (including the node
for the type's own name) before the declaration record; dependents that reach a tainted *inductive type* only through
that early node are therefore missed. Counts for seeds that are definitions or theorems and that propagate through
definitions and theorems agree with `depgraph`; counts that propagate through structure types are too low
(see the appendix "Correction to the earlier version" of the paper).

```bash
curl -LO https://math.mit.edu/~drew/grh/solution.ndjson.zst      # 7,699,933,588 bytes
shasum -a 256 solution.ndjson.zst
# expect 61a8938ad5f5e57397c1c0e3b954916af546d9004ade01c3555744a681b05381
zstd -d --long=30 solution.ndjson.zst                             # 61,570,595,788 bytes
shasum -a 256 solution.ndjson
# expect 5ea74b912147c5c93cc2b6d70cc727cf908df2f62ac6a20480a3fa02f6be244e

cd evidence/conescan && cargo build --release
mkdir out && cat /path/to/solution.ndjson | ./target/release/conescan out scan2/seeds.tsv scan2/watch.txt
```

`conescan OUTDIR SEEDS WATCH` reads a lean4export (format 3.x) NDJSON stream on stdin and writes
`OUTDIR/conescan_report.txt` plus one `tainted_bit*.tsv` per seed.

* `SEEDS`: one `label<TAB>pattern` per line (max 16). A pattern is a full constant name, `*.suffix`
  (match by trailing name components), or `PROJ:<structure full name>:<field index or *>`.
* `WATCH`: full names whose presence, kind and dependency bits are printed.

How it works: every expression node gets a 16-bit taint mask (a `const` node referring to a seed or to an
already-tainted declaration sets bits; compound nodes take the union of their children; a matching `proj`
node sets the bit of a `PROJ` seed). A declaration is tainted if its type or value is (for an inductive block:
any constructor type, recursor type or recursor rule). Because the export lists declarations after their
dependencies, one forward pass gives the exact set of declarations that transitively depend on each seed.
A "direct witness" is recorded per tainted declaration, which yields the dependency chains in the report.

It is a dependency analyser, **not** a type checker.

Our outputs:

* `conescan/scan1/` – first pass (hard-coded seeds; source kept as `src/main_v1_first_pass.rs`):
  `anyGeometry`, `geoOf`, `GeoCl.rec`, projection of `OAt.geo`, `plugAll`, `every_character_of_green_v_win`, `sorryAx`, `GeoCl`.
* `conescan/scan2/` – degenerate / junk / placeholder models.
* `conescan/scan3/` – eliminations and field projections of the geometry-carrying structures.

Each pass takes 5–15 minutes on the uncompressed file.

## 5. Rebuilding the challenge export from official Mathlib

Script and log: `challenge-rebuild/rebuild_challenge.sh`, `challenge-rebuild/rebuild_challenge.log`.
In short: a project containing only `Challenge.lean` (five statements with `sorry`, `import Mathlib`),
the original `lakefile.toml` / `lake-manifest.json` / `lean-toolchain`, Lean 4.33.1, `lake exe cache get`
(8,690 files from the official Mathlib cache; **make sure it does not start compiling Mathlib from source**),
`lake build Challenge`, then

```bash
lake env /path/to/lean4export/.lake/build/bin/lean4export Challenge -- $(cat export-targets.txt | tr '\n' ' ') > my_challenge.ndjson
shasum -a 256 my_challenge.ndjson
# we obtained bd484ac9886a96f26b1d9a7a59ebd45b7a70d102c015d4f31f9302bbdd6ab2b9 — byte-identical to the published file
```

## 7. Independent verification agents (Gemini 4 Neon)

Fourteen `agy --dangerously-skip-permissions --model gemini-4-neon-xhigh --print "<prompt>"` runs, read-only by
instruction, each from an empty context.

* Round 1 (claims as publicly summarized): prompts `agy/prompts/{A,B,C,D}.txt`, reports `agy/*.md`.
  Local absolute paths were rewritten to `~/rh-audit/...`; nothing else was edited.
* Round 2 (full text of the paper): prompts `agy/round2/prompts/{E,F,G,H}.txt`, reports `agy/round2/*.md`;
  see `agy/round2/README.md` for the three kinds of edit applied before publication.
* Round 3 (the minimal example of 24 November 2026): six further runs, prompts `agy/round3/prompts/{I,J,K,L,M,O}.txt`,
  reports `agy/round3/*.md`, the agents' test files in `agy/round3/work/`; see `agy/round3/README.md`.
